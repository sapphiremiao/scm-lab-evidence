Q1. Why is commit history useful?



Commit history shows every change, who made it and when. If a bug appears, I can check the history to find which commit caused it. 



Q2. Git vs GitHub



Git is a program on my computer that tracks changes. GitHub is a website that stores Git repositories online so people can share and work together. 



Q3. Why use a branch and pull request?



A branch lets me make changes without touching the main version. A pull request lets the changes be checked before they are merged. This lowers the risk of breaking main with mistakes.



Q4. Which commands changed my computer and which changed GitHub?



\-git init, git add, git commit, git switch, git merge and git branch -d only changed my computer. 

\-git push changed GitHub because it uploaded my commits there. 

\-git clone and git pull copied changes from GitHub to my computer.



Concept table



Repository: A project folder with its full history.

Working tree: The files I see and edit.

Staging area: Changes picked for the next commit.

Commit: A saved snapshot with a message.

Branch: A separate line of work.

Merge: Joining one branch into another.

Remote: A copy of the repo online, e.g. GitHub.

Push / Pull / Clone: Upload commits / download new commits / copy a repo for the first time.
